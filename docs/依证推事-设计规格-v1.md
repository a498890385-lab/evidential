## 1. 产品定义

### 1.1 一句话

一个**人机协作的依证推事**：输入一个待验证的判断，持续攒证据（手动 / AI 搜 / 贴链接 / 贴正文），每次加证据就更新后验概率，攒够了导出可复现的论证报告。

### 1.2 它和"让 AI 给结论"的区别

| | 普通 AI 问答 | 本工具 |
|---|---|---|
| 结论 | 一次性给出，不可追溯 | 由先验 + N 条证据逐步推出，每条可查 |
| 证据 | 混在回答里，真假难辨 | 独立条目，带引文/URL/来源可信度，用户逐条确认 |
| 更新 | 换个问法就变 | 加证据才变，变化量可解释（贝叶斯因子） |
| 长期 | 上下文一断全丢 | 会话可存几个月，随时续 |
| 反证 | 容易被忽略 | "反对方向"是必检项，报告里强制列出 |

### 1.3 典型使用节奏（贯穿案例）

用户问题：**"这个 SaaS 项目明年能盈利吗？"**

- 第 1 天：输入问题 → 设先验（同类项目第二年盈利比例 30%）→ 加 1 条证据 → 后验 28%
- 第 10 天：AI 搜到 5 条候选 → 采纳 2 条、否决 3 条 → 后验 41%
- 第 30 天：贴进来一份融资新闻链接 → 解析出 1 条不利证据 → 后验 33%
- 第 60 天：补了 4 条 → 后验 46%，但敏感性面板红着（一条中等反证就能翻盘）→ 继续搜
- 第 90 天：三灯全绿 → 记录判断 → 导出报告

### 1.4 范围

**做**：多会话管理、竞争假设、先验（参照类分层）、证据链、五档似然、相关性折扣、概率轨迹、敏感性分析、决策阈值、证据充足度、AI 搜索/链接解析/正文解析、候选队列、判断记录、Markdown/PDF 报告、导入导出、本地备份。

**不做**（v1 明确排除）：账号与云同步、多人协作、自动定时抓取（留接口）、多设备同步、移动端、任何"系统自动替用户下结论"的功能。

## 3. 数学内核（正式规格）

### 3.1 表示

- 概率域只用于输入/显示，内部一律 **log-odds**：
  `logit(p) = ln(p / (1-p))`，`p = sigmoid(x) = 1/(1+e^{-x})`
- 单假设对：`logit(P(H|E)) = logit(P(H)) + ln(P(E|H)/P(E|¬H))`，第二项记为 `logBF`。
- 概率裁剪区间：`[0.005, 0.995]`（logit ∈ [-5.293, 5.293]）。裁剪发生时打 `saturated` 标记，UI 提示"影响已饱和"。

### 3.2 多假设更新

假设集合 `H₁..Hₙ`（2 ≤ n ≤ 6），先验 `πᵢ = P(Hᵢ)`，Σπᵢ = 1。

对证据 E，用户为每个 Hᵢ 提供相对基准 H_b 的似然比 `rᵢ = P(E|Hᵢ)/P(E|H_b)`（`r_b = 1`）。取 `P(E|H_b) = c`，则 `P(E|Hᵢ) = c·rᵢ`，归一化后：

```
log wᵢ = ln(πᵢ) + ln(rᵢ)
P(Hᵢ|E) = exp(log wᵢ) / Σⱼ exp(log wⱼ)
```

二元时 `r₂ = 1/r₁`，退化为 §3.1。归一化用 log-sum-exp 避免下溢。

### 3.3 似然输入的三个通道

**通道 A：五档（默认，n=2）**

| 档位 | 用户看到的话 | LR = P(E\|H)/P(E\|¬H) | logBF | Kass–Raftery 强度 |
|---|---|---|---|---|
| A1 几乎必然 | 假设为真则几乎一定见到；假设为假则几乎不会 | 5 | +1.61 | 中等（3–10） |
| A2 更可能 | 假设为真时更常见 | 2 | +0.69 | 弱（1–3） |
| A3 无差别 | 真假两种情况一样常见 | 1 | 0 | 无信息 |
| A4 更不可能 | 假设为假时反而更常见 | 1/2 | −0.69 | 弱（1–3） |
| A5 几乎不可能 | 假设为真则几乎不会见到 | 1/5 | −1.61 | 中等（3–10） |

档位 ↔ LR 的映射固定写死在 `domain/tiers.ts`，报告里引用同一常量（防止两处口径漂移）。
分档依据：Kass–Raftery 的 BF 分级（1–3 微弱 / 3–10 中等 / 10–30 强 / 30–100 很强 / >100 决定性）。本表刻意只用 5 与 2 两档，避免用户高估证据强度。

**通道 B：自然频率**

UI 问："1000 个『假设成立』的情形里，大约多少个能见到这条证据？____ / 1000"，同样再问一次"假设不成立"的情形。
`LR = (x_H/1000) / (x_¬H/1000) = x_H / x_¬H`（x_¬H=0 时取 1/1000 兜底并提示）。
理由：自然频率比条件概率好估一个量级（刘 §9 医学章的思路）。

**通道 C：数值**

高级用户直接填 LR（0.05–20）。填 1 等于"无信息"，系统提示"1:1 的证据加进去不会改变任何东西"。

**一致性规则**：一条证据只有一种通道生效，切换通道时保留上一次的值。所有通道最终都归一到 `lr: Record<HypId, number>`。

### 3.4 先验：参照类分层

```
PriorSource {
  mode: 'reference-class' | 'direct' | 'uniform'
  layers: [ 粗 → 细 ]   // 每层：描述 + 基准率 + 数据出处
  chosenLayerId
}
```

- 用户可填 1–5 层，例：`北京考生 36.3%` → `人大附中考生 100%`（刘 §7.5 的原文例子）。
- 取**最细且填了基准率**的那一层作为先验来源；更粗的层在报告里作为参照保留。
- 全部留空 → `uniform`（二元时 50/50），UI 黄条提示"先验未设，结论对先验极度敏感"。
- 直接模式：二元时给一个 0.01–0.99 的滑块（老用户习惯），但默认展开分层模式。
- 多假设时：逐层给每个假设一个基准率并归一化；层内和为 1 由系统强制。

### 3.5 相关性折扣

证据可归组（同源报道、同一事件、同一调查）。组内第 1 条全额，其余按强度折扣：

| 强度 | ρ | α = 1−ρ | 效果 |
|---|---|---|---|
| 强相关（同一件事换说法） | 0.7 | 0.3 | logBF 只取 30% |
| 中等相关 | 0.4 | 0.6 | 取 60% |
| 弱相关 | 0.2 | 0.8 | 取 80% |

`logBF_eff = α · logBF`。不做"完全独立"的承诺：默认不分组（α=1），UI 在检测到"同一域名 ≥3 条""标题高度相似"时提示分组。

**已知局限（写进报告）**：这是工程近似，严格做法要用联合分布/图模型；α 由用户选，选错会高估或低估。报告里必须列出所有被打折的证据。

### 3.6 派生值不可变

会话里**不存**任何"权威概率"。唯一的输入是 `π` + `evidence[]`（含顺序），其余全部由纯函数重放：

```
replay(session) -> { steps: Step[], final: Posterior, flags }
Step = { seq, evidenceId, before, after, logBF_eff, saturated }
```

删除/编辑/重排/改折扣 → 重放整条链。这样"改早期证据后自动重算"不需要任何特殊代码路径，也不会出现两份真值。

### 3.7 敏感性分析

| 分析 | 做法 | UI 呈现 |
|---|---|---|
| 单点依赖 (LOO) | 逐条移除证据重放，记录终值变化 | 按 \|Δ\| 排序的条形图，最大的标红 |
| 先验扰动 | 先验 ±10、±20 个百分点（裁剪到 [0.01,0.99]）各重算终值 | 四行小表 + "结论是否翻转" |
| 翻转所需反证 | `ΔlogBF = logit(阈值) − logit(当前)` | 一句话："还需约 X 条中等强度反证才能跌破阈值"（log 2 ≈ 0.69 折算） |
| 区分度 | 每条证据 \|logBF_eff\| < 0.2 标记"弱证据" | 灰显 + 计数 |

### 3.8 决策阈值

用户填行动成本 `c` 与不行动损失 `b`（同单位，货币或主观分），阈值

```
p* = c / (c + b)
```

也可直接填 `p*`。报告输出三类判定：`p < p* → 不建议行动`；`p* ≤ p < p*+0.15 → 临界，需更多证据`；`p ≥ p*+0.15 → 支持行动`。**概率本身不是结论**（奇弗斯 §3）。

### 3.9 证据充足度（四灯）

在"记录判断/导出报告"前计算：

| 灯 | 条件 | 默认判据 |
|---|---|---|
| 稳健 | 先验 ±20 点内结论不翻转 | 4 次扰动后 `verdict` 相同 |
| 无单点依赖 | 任何一条证据被移除都不翻转 | LOO 全部同 verdict |
| 双向覆盖 | 至少 1 条被采纳的反证，或用户勾选"已检索反对方向且未找到" | 有记录即可 |
| 相关性已处理 | 不存在"≥2 条同源且未打折"的证据 | 无黄项 |

三绿一黄 → 允许导出但报告显著标注；全绿 → "可以下结论"；任一红 → 导出按钮仍可用，但报告首页会打印"证据不充分"的可能性说明。

### 3.10 精度与显示

- 内部 float64，不使用整数化。
- 显示：概率 1 位小数（46.2%）；胜率 2 位（2.11 : 1）；logBF 2 位；BF <0.01 或 >100 时用科学计数。
- 报告里给出"可复现算式"：`logit(30.0%) = −0.847; +0.693 (E1) = −0.154 → 46.2%`，让读者能自己验算。

### 3.11 明确写清的数学局限

1. **似然值是主观估计**：输出的是"你的信念量化"，不是客观频率。报告首页固定声明。
2. **独立性只是近似**：折扣只能缓解，不能消除。
3. **顺序效应**：无裁剪时链式更新与顺序无关；有裁剪/折扣时与顺序有关。报告里的"影响幅度"以当前顺序为准。
4. **证据的语义**：一条证据必须是"一个可判真假的命题 + 观测条件"。同一新闻的五篇转载算 1 条（分组）而不是 5 条。

## 4. 数据模型

```ts
// domain/types.ts
type ID = string;
type ISO = string;

interface Session {
  id: ID;
  schemaVersion: 1;
  title: string;
  question: string;
  status: 'active' | 'concluded';
  createdAt: ISO;
  updatedAt: ISO;
  hypotheses: Hypothesis[];        // 2..6, prior 和为 1
  priorSource: PriorSource;
  evidence: Evidence[];            // 按 seq 有序；含已否决
  groups: CorrelationGroup[];
  candidates: Candidate[];         // 待确认队列，不入链
  assessments: Assessment[];       // "记录判断"快照
  decision: DecisionConfig;
  aiLog: AiRun[];
  notes?: string;
}

interface Hypothesis {
  id: ID;
  label: string;        // ≤12 字，用于 tab/图例
  statement: string;    // 完整陈述
  prior: number;        // 归一到和为 1
  isBaseline?: boolean; // 似然矩阵基准，默认第一个
}

interface PriorSource {
  mode: 'reference-class' | 'direct' | 'uniform';
  layers: ReferenceLayer[];   // 粗 → 细
  chosenLayerId?: ID;
  direct?: Record<ID, number>; // 直接模式的 (hypId -> p)
  note?: string;
}

interface ReferenceLayer {
  id: ID;
  description: string;   // "2021 年北京考生"
  baseRate?: Record<ID, number>; // (hypId -> p)，层内和为 1
  source?: string;       // 出处/URL
}

interface Evidence {
  id: ID;
  seq: number;
  claim: string;                 // 一句话命题（强制："可判真假"）
  detail?: string;               // 展开说明
  kind: 'observation' | 'statistic' | 'testimony' | 'document' | 'inference';
  sourceType: 'user' | 'ai_search' | 'link' | 'paste';
  provenance?: {
    url?: string; title?: string; site?: string;
    quote?: string;              // 必须能在正文中找到（AI 来源时强制校验）
    retrievedAt?: ISO; searchQuery?: string;
  };
  lr: Record<ID, number>;        // 相对 baseline 的似然比，baseline = 1
  lrInput: { mode: 'tier' | 'frequency' | 'direct'; raw?: unknown }; // 回显输入方式
  reliability: 'high' | 'medium' | 'low';
  groupId?: ID;
  status: 'adopted' | 'rejected';
  createdAt: ISO;
  tags?: string[];
}

interface CorrelationGroup {
  id: ID; label: string;
  strength: 'strong' | 'medium' | 'weak';
  note?: string;
}

interface Candidate {
  id: ID;
  createdAt: ISO;
  claim: string;
  detail?: string;
  kind: Evidence['kind'];
  provenance: NonNullable<Evidence['provenance']>;
  suggestedLr: Record<ID, number>;
  reason: string;            // AI 为什么这么建议（展示给用户，不参与计算）
  reliability: 'high' | 'medium' | 'low';
  provenanceCheck: 'verified' | 'unverified' | 'missing'; // quote 溯源校验结果
  direction: 'support' | 'oppose' | 'neutral';
  state: 'pending' | 'adopted' | 'rejected';
}

interface Assessment {
  id: ID;
  at: ISO;
  posterior: Record<ID, number>;
  verdict: 'below' | 'borderline' | 'above';
  sufficiency: { stability: boolean; noSinglePoint: boolean; bothSides: boolean; correlation: boolean };
  userConclusion: string;   // 用户自己写的一句话
  nextStep?: string;
}

interface DecisionConfig {
  actionCost?: number;
  inactionCost?: number;
  threshold?: number;      // 0..1，默认由 c/(c+b) 推出
  actionLabel?: string;    // "投入下一轮开发"
}

interface AiRun {
  id: ID; at: ISO;
  kind: 'queries' | 'search' | 'extract' | 'parse-link' | 'parse-paste' | 'alt-hypotheses' | 'open-questions';
  model?: string; query?: string; url?: string;
  ok: boolean; error?: string;
  tokens?: { in: number; out: number };
  resultCount?: number;
}

interface Settings {
  llm: { baseUrl: string; model: string; apiKeyEnc?: string };
  search: { provider: 'deepseek' | 'bocha'; apiKeyEnc?: string; count: number };
  ui: { theme: 'light' | 'dark'; density: 'compact' | 'comfortable' };
}
```

**校验规则**（写入前强制）

- `hypotheses.length ∈ [2,6]`，`Σprior = 1 ± 1e-9`。
- `Σ lr` 无意义，但每个 `lr ∈ [0.02, 50]`，baseline 必须为 1。
- `seq` 唯一且连续；`status='adopted'` 的条目才参与计算。
- `groupId` 必须存在；组内 ≥2 条才有折扣。
- AI 来源的证据 `provenance.quote` 非空且通过溯源校验（§5.4），否则 `reliability` 最高只能记 `medium`。

## 5. AI 证据子系统

### 5.1 Provider 抽象

```ts
interface LlmProvider {
  chat(req: { system: string; user: string; json?: boolean; temperature?: number }): Promise<string>;
}
interface SearchProvider {
  search(q: string, opts: { count: number; content?: boolean }): Promise<SearchResult[]>;
}
interface SearchResult {
  title: string; url: string; snippet: string; summary?: string;
  content?: string; site?: string; publishedAt?: string;
  authority?: number;   // DeepSeek: 0–4；Bocha: 无（用域名规则兜底）
  score?: number;       // rerank_score / 相关性
}
```

**DeepSeek 适配**（推荐默认）
- LLM：`POST https://api.deepseek.com/chat/completions`，`model: deepseek-flash`，`response_format: {type:'json_object'}`。
- 搜索：`POST https://api.deepseek.com/v1/tools/search`，body `{query, count, ori_question, need_content:true}`，返回 `results[]{title,url,snippet,summary,content,site_name,date,authority,rerank_score}`。
- 一把 Key 两个能力，且直接拿到正文 → 不需要额外的网页抓取模块。

**博查适配**
- `POST https://api.bochaai.com/v1/web-search`，header `Authorization: Bearer <key>`，body `{query, count, summary:true, freshness:'noLimit'}`，返回 `data.webPages.value[]{name,url,snippet,summary,siteName,datePublished}`。
- 正文需要单独抓取（主进程 `fetch` + 简易正文抽取：取 `<article>`/最长文本块，丢导航脚本，截断 6000 字）。

字段以联调实测为准；适配器输出统一 `SearchResult`，UI 与后续流程不感知供应商差异。

### 5.2 四个 prompt

**P1 检索词生成**（输入：问题 + 本次目标假设 + 已有证据摘要）
输出 JSON：
```json
{ "support": [{"query":"…","angle":"政策/财报/用户口碑"}],
  "oppose":  [{"query":"…","angle":"…"}],
  "rationale": "为什么这些角度还没覆盖" }
```
硬约束：`support`、`oppose` 各 ≥2 条；每条 query ≤32 字；不得与已有证据的 query 重复；必须给 angle。

**P2 证据提取**（输入：一条搜索结果正文 + 问题 + 假设列表 + 已有证据命题）
输出 JSON 数组，每条：
```json
{ "claim": "一句话可判真假的命题",
  "detail": "展开",
  "kind": "statistic|observation|testimony|document|inference",
  "quote": "原文片段，必须逐字出现在正文中",
  "direction": "support|oppose|neutral",
  "lr": {"H1": 3, "H2": 1},
  "reason": "为什么给这个 LR（如：若项目盈利，续约率数据应更常见…）",
  "reliability": "high|medium|low",
  "reliabilityReason": "机构/个人/自媒体/无署名" }
```
硬约束：`quote` 必须来自正文；`lr` 只允许落在 {0.2, 0.5, 1, 2, 5} 或明确说明理由的数值；`reason` 必须写"在假设真假两种世界里该证据的常见度对比"，禁止写"这条证据支持/反对该假设"式空话。

**P3 备择假设生成**（输入：当前假设 + 已有证据）
输出 1–3 个"第三种解释"，每个含：`label`、`statement`、`whyItExplainsTheSameData`。触发条件：两条假设对该证据的 logBF 都 < 0.2（解释力接近）。

**P4 剩余不确定点**（输入：证据链摘要 + 假设 + 未覆盖角度）
输出 3–6 条："还有哪些方向没有证据""哪些关键变量尚未验证""哪条证据如果被推翻影响最大"。只产文本，不入链。

### 5.3 候选 → 采纳流程

```
AI 搜索/解析
   → 候选列表（状态 pending，不入链）
   → 用户逐条：[采纳] [修改后采纳] [否决] [打开原文]
   → 采纳时确认 lr（AI 给的是建议值，用户可改，默认折中）
   → 入链（seq 追加）→ 重放 → 图表刷新
```

- 候选卡片必须显示：命题、原文引文（高亮）、域名、发布时间、AI 建议 LR + 理由、溯源校验结果。
- 一键"全部采纳"默认**不提供**（防批量污染）。多选后需逐条确认 LR 的分步向导。

### 5.4 溯源校验

`quote` 归一化（去空白、全角转半角、去零宽字符）后必须出现在 `content`（或 `summary`）中。校验失败 → `provenanceCheck='unverified'`，卡片标黄"AI 引文未能在正文中定位，请人工核对"，且不允许 `reliability='high'`。

### 5.5 去重

- 入候选前按 `url` 规范化去重；标题相似度（去标点后 Jaccard ≥0.85）视为重复，保留权威度高的。
- 与已有证据的 `claim` 相似（字符 3-gram Jaccard ≥0.8）→ 标记"疑似与 E5 重复"，提示归组而不是重复入链。

### 5.6 失败与限流

| 场景 | 行为 |
|---|---|
| LLM 401/403 | 设置页高亮"Key 无效"，不阻塞本地推理功能 |
| LLM 429 | 指数退避 2 次，仍失败提示"稍后再试"，保留已有结果 |
| LLM 返回非 JSON | 重试 1 次（temperature 降到 0.2），仍失败显示原始文本 + "解析失败" |
| 搜索 0 结果 | 提示"换个角度/关键词"，记录到 aiLog |
| 搜索超时（15s） | 中止并提示，不影响已有证据链 |
| 链接打不开 | 提示"无法解析，请手动粘贴正文" |

### 5.7 成本与隐私

- 每次搜索默认取 8 条结果，正文截断 6000 字/条，单次提取最多 3 条结果（防止 token 爆炸）。
- 界面显示本次会话累计 token 与估算成本（按用户填的单价，默认 DeepSeek 现价）。
- 只发送：问题文本、假设、已有证据的**命题**（不发引文与URL）；设置页可关闭"发送证据摘要"。
- API Key 用 Electron `safeStorage` 加密后落盘；导出 `.bayes` 文件时**剔除** Key。

### 6.2 各面板规格

**左栏 · 问题与假设**

## 7. 报告

### 7.1 结构（十节，顺序固定）

1. **结论摘要**：问题、当前后验、相对阈值的判定、置信等级、一句话结论
2. **假设与先验**：竞争假设表、先验来源（参照类分层 + 出处）、归一化后的先验
3. **证据链**：逐条（命题、来源与引文、LR 与依据、前后概率、Δ、可信度、组与折扣）
4. **概率轨迹**：表 + 图（SVG）
5. **敏感性分析**：LOO 表、先验扰动表、翻转所需反证
6. **证据充足度**：四灯 + 每灯的理由
7. **弱证据与相关问题清单**：区分度低的、被折扣的、可信度低的
8. **剩余不确定点**：AI 生成（可编辑）+ 用户补充
9. **判断记录**：每次判断的时间、后验、用户结论、下一步
10. **方法与免责声明**：公式、log-odds 明细、主观概率声明

### 7.2 Markdown 模板（节选）

````markdown
# 依证推事报告 · {title}

> 生成时间：{YYYY-MM-DD HH:mm}　证据 {N} 条（采纳 {K} / 否决 {M}）　模型：{model}

## 1. 结论摘要

- **问题**：{question}
- **当前后验**：{H1.label} {p1}　{H2.label} {p2}
- **胜率**：{odds} : 1（贝叶斯因子累计 ×{BF}）
- **决策阈值**：{p*}（行动成本 {c} / 不行动损失 {b}）
- **判定**：{above|borderline|below} — {结论句}
- **置信等级**：{高|中|低}（依据：证据 {N} 条，充足度 {三绿|有黄|有红}）

## 2. 假设与先验

| 假设 | 陈述 | 先验 |
|---|---|---|
| H1 | {statement} | 30.0% |
| H2 | {statement} | 70.0% |

先验来源：参照类分层（粗→细）
1. 2021 年北京考生一本率 36.3%（来源：…）
2. 人大附中一本率 100%（来源：…）← 采用

## 3. 证据链

### E1 · {claim}
- 来源：{site}（{url}），2026-10-08
- 原文引文：> {quote}
- 似然比：P(E|H1)/P(E|H2) = 2 : 1（档位"更可能"）
- 影响：30.0% → 46.2%（+16.2，logBF +0.69）
- 可信度：高（上市公司年报）
- 相关性：无（独立）

## 4. 概率轨迹

| # | 证据 | 概率 | 胜率 | 累计 BF |
|---|---|---|---|---|
| 0 | 先验 | 30.0% | 0.43:1 | — |
| 1 | E1 | 46.2% | 0.86:1 | 2.00 |
| 2 | E2 | 30.0% | 0.43:1 | 1.00 |

## 5. 敏感性分析

- 移除任一条证据后，结论是否翻转：否（最大变动：移除 E3 → 41.1%）
- 先验 ±20 点：29.8%–48.9%，结论不翻转
- 再需约 **0.25 / 0.69 ≈ 1 条**中等强度反证即可跌破阈值 → **结论脆弱**
````

## 9. 开发计划与验收

### P1 内核（纯 TS + 单测，无 UI）

交付：`domain/*` 全套 + `tests/*`。
验收（`pnpm test` 全绿，含以下固定用例）：

1. 耳科例子回归：似然比 2.25 : 1 支持"脑瘤"，基准率 11/百万 vs 37 000/百万 → 后验胜率（脑瘤 : 耳垢）≈ 1 : 1508，相对误差 <1%（对应 P(脑瘤|症状) ≈ 0.00066）。
2. 五档 LR 常量与 logBF 对照表一致。
3. 多假设：三假设、任意 lr 向量，归一化和为 1，且与逐对贝叶斯结果一致。
4. 折扣：α=0.6 时 logBF 精确乘 0.6。
5. 裁剪：极端 LR 连乘后停在 0.995，且 `saturated=true`。
6. 回放幂等：重放两次结果相同；乱序插入后按 seq 重排结果一致。
7. LOO：移除某条后终值与单独计算一致。
8. 翻转所需反证：解析解与数值扫描一致。

### P2 界面骨架

交付：三栏 UI、会话管理、证据 CRUD、先验分层、图表、充足度、自动保存。
验收：完整走一遍 §1.3 案例；关掉重开数据不丢；删除中间证据后所有后验正确重算；图表与数字一致。

### P3 AI

交付：设置页、搜索/链接/正文解析、候选队列、备择假设、溯源校验、AI 日志。
验收：用真实 Key 跑通"搜索→候选→采纳→后验变化"，且候选入链前后手算一致；断网/错误 Key/429 三种失败态有清晰提示且不丢数据。

### P4 报告与打包

交付：MD/PDF 导出、导入导出、打包 exe、图标。
验收：双击 exe 可用；导出的 PDF 在 Adobe/Edge 打开正常、图表清晰、页脚正确；报告里的算式能手工复算。

## 附录 A · 术语表

| 术语 | 符号 | 说明 |
|---|---|---|
| 先验 | P(H) | 看到证据前的信念 |
| 似然 | P(E\|H) | 假设真时出现该证据的概率 |
| 似然比 / 贝叶斯因子 | LR = P(E\|H)/P(E\|¬H) | 证据有多"值钱" |
| 后验 | P(H\|E) | 更新后的信念 |
| log-odds | logit(p) = ln(p/(1−p)) | 内部的加法表示 |
| 胜率 | odds = p/(1−p) | 后验胜率 = 先验胜率 × BF |
| 决策阈值 | p* = c/(c+b) | 行动成本与不行动损失的比值 |

## 附录 B · 似然比速查

| 场景 | 建议档位 | LR |
|---|---|---|
| 只有该假设能解释的现象（如只有盈利才可能签下的合同） | 几乎必然 | 5 |
| 该假设下更常见（如行业整体增长带动） | 更可能 | 2 |
| 两种假设下都常见（如"团队很努力"） | 无差别 | 1 |
| 该假设下反而少见（如亏损时才会有的裁员） | 更不可能 | 1/2 |
| 几乎不可能（如已有法院终审判决造假） | 几乎不可能 | 1/5 |

## 附录 C · 与原始开发者文档的差异

| 项 | 原文档 | 本规格 | 原因 |
|---|---|---|---|
| 先验输入 | 0–100% 滑块 | 参照类分层（可回落滑块） | 刘 §7.5：基准率必须来自可查数据 |
